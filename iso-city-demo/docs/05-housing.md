# 05 · 社区与住宅（1:1 真实比例）

这一章重做“认领房子、在这里生活”的核心玩法：楼怎么分类、住宅怎么生成、怎么进楼、房子为什么稀缺，以及社区里的公共设施。
本文档取代之前的“每栋楼一条长走廊 + 平均切开间”方案（`shared/units.mjs` 里的 `floorPlanOf`）。

---

## 1. 核心决策

### 决策 A：表里如一，一切按 1:1 真实比例

- 街上看到的楼、电梯厅、户内、阳台**全部来自同一份数据**。外面的每一扇窗、每一个阳台，在户内都能找到对应的那一面墙。
- 楼体尺寸、层高（3.3m）、户型面积、门窗尺寸都按现实取值，不再“外面一个比例、里面一个比例”。

### 决策 B：小而密，先做一个社区

- 只做**一个可玩社区**，约 200m × 160m，以中央广场为中心，从任何一户走到广场不超过一分钟。
- **能进去的地方一定有内容，进不去的就是布景。**不做空的写字楼室内，不单独建商场。
- 社区外面是 CBD 玻璃塔群和天际线，只负责“繁华都市”的观感，不能进。
- 城市靠“开盘”扩张：社区住满后再开新片区（见第 9 节）。

### 决策 C：按建筑类型生成平面，住宅不再是宾馆结构

| 类型 | 平面 | 1 楼 | 立面 | 一期是否可进 |
|---|---|---|---|---|
| 住宅·板楼 | 2~3 个单元并排，一梯两户或一梯三户，**户型南北通透** | 商铺 + 侧面或背面的单元入口 | 按户型反推：客厅阳台、卧室窗、厨卫小窗、空调格栅 | ✅ |
| 住宅·塔楼 | 核心筒居中，一梯四到六户 | 商铺 + 入户大堂 | 同上，四面都有户 | ✅ |
| 青年公寓 | 短内廊，小户型 | 商铺 + 大堂 + 公共客厅 | 规则的小窗 | ✅ |
| 酒店 | 内廊 | 前台大堂 | 均匀的小窗 + 大雨棚 | ✅ 新手临时房 |
| 写字楼 / 地标塔 | 核心筒 + 大平层 | — | 玻璃幕墙或均匀窗格 | ❌ 只展示 |

### 决策 D：户内一期是大开间，面积照现实

- 户内不分隔墙，就是一个完整的大开间；面积、开间、进深、门窗位置全部照真实户型。
- 以后再加**自由隔墙和家具**，总面积不变。

### 决策 E：稀缺性靠“各有特色”，不靠“有好有坏”

每种房子都有别处没有的东西：江景房有江景和私人钓位，复古楼有小院，顶层有私人露台……玩家按喜好选，而不是都去抢最大最高的那套。详见第 7 节。

## 2. 社区布局

### 2.1 平面示意（暂定，H1 里程碑按实际地形微调）

```
                北
   ┌──────────────────────────────────────────┐
   │  [高层塔楼]          [青年公寓]            │
   │       │                  │                │
   │  [复古板楼]─── 中央广场（摊位·喷泉）─── [酒店] │
   │       │       雪松巷夜市   中巷创意街       │
   │       │           │                       │
   │   小公园     摩天轮 ── 码头 ── 河岸步道     │
   │ ~~~~~~~~~~~~~~~~~ 河 ~~~~~~~~~~~~~~~~~~~~ │
   │              [江景板楼]（面朝河）           │
   └──────────────────────────────────────────┘
     外围：CBD 玻璃塔群 / 天际线（只展示，不能进）
```

- 社区以现有的中央广场 `plaza (-29, 6)` 为中心。
- **新增一条河**横穿社区南侧，提供钓鱼、江景、游船和码头。现在主城还没有水域。
- 摩天轮、码头、河岸步道连成一条“滨水线”，是社区最热闹、拍照最好看的地方，江景板楼正对着它。
- 社区边缘用河、绿化带或高架挡一下，过渡到外围布景时不显得突兀。

### 2.2 楼栋清单

| 楼 | 现有 id | 定位 | 平面 | 每层户数 | 层数 | 主力户型 | 目标尺寸（宽×深×高） |
|---|---|---|---|---|---|---|---|
| 复古板楼 | `west-residence` 雪松公寓 | 复古翻新 | 板楼，2 单元 × 一梯三户 | 6 | 7 | 60~80㎡ | 52 × 12 × 25m |
| 江景板楼 | `riverside` 河岸公寓 | 江景改善 | 板楼，3 单元 × 一梯两户 | 6 | 18 | 110~140㎡ | 75 × 14 × 62m |
| 高层塔楼 | `north-tower` 北塔 | 高层刚需 + 改善 | 塔楼，一梯六户 | 6 | 28 | 70~110㎡，混合 | 30 × 28 × 96m |
| 青年公寓 | `south-east` 塔下小楼 | 青年公寓 | 短内廊 | 10 | 10 | 45~60㎡ | 32 × 20 × 35m |
| 港湾酒店 | `harbor-hotel` | 新手临时房 | 内廊 | 16 | 12 | 35㎡ 标间 | 40 × 18 × 42m |

**容量**：住宅约 6×7 + 6×18 + 6×28 + 10×10 ≈ **420 户**（1 楼是商铺，实际再少一层），加上酒店约 170 间临时房，足够支撑前期。

**其余现有的楼**：
- `gallery` 光盒美术馆、`cafe` 街角咖啡、`soundfield` 声场唱片：保留，作为社区里的公共室内空间（已经有室内）。
- 其他十几栋：一期全部改成**不能进的外观楼**，挪到外围组成 CBD 玻璃塔群和天际线。

### 2.3 各栋风格

| 楼 | 风格 | 立面要点 | 夜景 |
|---|---|---|---|
| 复古板楼 | 红砖翻新（干净、有格调，不是破旧） | 红砖、白色窗套、拱窗、铁艺阳台栏杆、爬墙绿植 | 暖黄色窗灯，阳台灯串比例高 |
| 江景板楼 | 现代改善 | 大面宽阳台、**玻璃栏板**、白色横向楼板线 | 每层楼板线暗藏灯带 |
| 高层塔楼 | 现代高层 | 浅灰涂料、竖向装饰线、空调格栅 | 楼顶灯冠 |
| 青年公寓 | 简洁现代 | 规则的方窗、彩色窗框 | 窗灯颜色最多样 |
| 港湾酒店 | 酒店 | 均匀小窗、入口大雨棚、招牌 | 招牌 + 雨棚灯 |
| CBD 布景塔 | 玻璃幕墙 | 竖挺、反射天空 | 冷白窗灯 + 顶部灯带 |

## 3. 住宅生成规则

### 3.1 楼层规则

| 楼层 | 内容 |
|---|---|
| 1 楼 | **临街商铺**（一期只做外观，二期开放成个人店铺）+ 单元入户大堂（开在侧面或背面） |
| 2 楼 | 标准层；底商屋顶变成 2 楼住户的**私家露台** |
| 标准层 | 从下到上重复同一套户型组合 |
| 顶层 | **复式或大平层**，带屋顶私人露台 |
| 屋顶 | 公共天台（允许烟花的片区才有） |

### 3.2 户型库

| 户型 id | 名称 | 面积 | 面宽 × 进深（参考） | 外立面组合（前 / 后） |
|---|---|---|---|---|
| `s1` | 一室一厅 | 45~60㎡ | 5.4 × 10 | 客厅阳台 / 卫生间小窗 |
| `m2` | 两室一厅 | 70~90㎡ | 7.5 × 11 | 客厅阳台 + 卧室窗 / 卧室窗 + 厨房小窗 |
| `m3` | 三室两厅 | 95~120㎡ | 9.6 × 12 | 客厅阳台 + 主卧窗 / 两个卧室窗 + 厨房小窗 |
| `l3` | 大三室 | 120~140㎡ | 11 × 12.5 | 宽阳台 + 主卧飘窗 / 卧室窗 ×2 + 厨卫小窗 |
| `l4` | 四室 / 大平层 | 140~240㎡ | 14+ × 13+ | 通长阳台或落地窗，四面采光（塔楼角户） |
| `h1` | 酒店标间 | 35㎡ | 4 × 8.5 | 一扇窗 |

- 每个户型带一个**立面图案**：沿面宽方向排列的开口序列，例如 `m2` 正面是 `[客厅阳台 4.2m, 墙 0.3, 卧室窗 2.4m]`。街上的楼体立面和户内的墙都按这个序列生成。
- **同一层可以有不同户型**：
  - 板楼一梯三户：两个边户用 `m2`，中间户用 `s1`
  - 塔楼一梯六户：两个角户用 `m3` 或 `l3`，四个中间户用 `s1` 或 `m2`
- 每栋楼的户型组合由定位决定（第 2.2 节），**按种子固定**，刷新不变。

### 3.3 户内（一期）

- 一个完整的矩形大开间，宽 = 户型面宽，深 = 户型进深，净高 3.1m。
- **板楼户是南北通透的**：前墙对应客厅阳台和卧室窗，后墙对应卧室窗和厨房小窗，都能看到外面。
- 塔楼角户两面有窗，中间户一面有窗。
- 入户门 1.5 × 2.35m 洞口、1.24m 门扇，和电梯厅那一侧的门是同一扇。
- 家具上限、画框位、宠物位按面积档位走（第 7.1 节）。

### 3.4 门牌号

真实格式：`河岸公寓 2 单元 1203`（单元 2，12 层，03 户）。

新空间 id：`${buildingId}-u${单元}-${层}${户}`，例如 `riverside-u2-1203`。地下层用 `b1`。

## 4. 进楼流程

```
临街单元门 → 1 楼入户大堂 → 电梯 → 本层电梯厅（2~6 扇户门）→ 进户
```

- **入户大堂**：门厅、信报箱、电梯、单元号牌。宠物可以在大堂里活动。
- **电梯厅**：一个小厅，没有长走廊。每扇户门旁显示门牌号、主人昵称或头像，门口可以放迎宾地垫或一盆植物，作为给访客的预览。
- **青年公寓**：电梯出来是一段短内廊，两侧各 5 户，中间有一个公共客厅。
- **酒店**：电梯出来是内廊，两侧是标间（现在的走廊结构正好合适）。

## 5. 立面

### 5.1 原则

- 住宅立面**从户型反推**：哪里是客厅就有阳台，哪里是卧室就有窗，空调机位跟着卧室走。
- 写字楼和 CBD 布景塔保留现在的程序化窗格着色器（`createFacadeMaterial`），玻璃幕墙负责天际线的繁华感。

### 5.2 让住宅好看的元素

| 元素 | 作用 |
|---|---|
| 玻璃栏板阳台 | 反射天空，整栋楼的质感一下就上来了 |
| 白色横向楼板线 | 每层阳台板外露成一条白线，形成横向节奏 |
| 竖向装饰线条 | 打破横向的单调，让楼显得更高 |
| 空调格栅 | 把空调机位藏起来，立面干净 |
| 楼顶灯冠 | 每栋楼顶有自己的造型和灯带，夜里好认 |

### 5.3 夜景

- 住宅窗灯是**暖色、随机、多样**的：有窗帘、电视的蓝光、阳台灯串。这是“万家灯火”，比写字楼整齐的冷白灯好看。
- **被认领的户晚上亮灯**，主人在线时灯更暖一些。抬头看到亮着的窗，就是真的有人住。
- 阳台装饰（植物、灯串、旗子）从街上能看到。

### 5.4 实现要点

- 街上的楼体（`src/scene/Building.tsx`）和户内看到的本栋楼壳（`src/indoor/CityBackdrop.tsx` 里的 `OwnShell`）调用**同一个立面生成函数**。
- 阳台板、栏杆、空调格栅全部合批：一栋楼增加的 draw call 不超过 4 个。
- 远处（>120m）只保留体量和窗灯，不画阳台几何。

## 6. 1 楼商铺与摆摊（二期）

### 6.1 展示位系统

店铺和摊位共用一套“展示位”数据，只是规则不同：

| | 1 楼店铺 | 路边摊位 |
|---|---|---|
| 占用方式 | 长期认领（一人一间） | 每人每天 1 个，4 小时，可续 1 次 |
| 数量 | 少，稀缺 | 多 |
| 外观 | 橱窗 + 招牌 + 门头 | 小摊 + 遮阳伞 + 小牌子 |
| 内容 | 标题、封面、展品图文、访客点赞和留言 | 同左 |
| 交易 | 前期不做；以后最多加“口粮换宠物饰品”这类轻量兑换 | 同左 |

### 6.2 城市分区与摊位区

**中央广场一个摊位都不摆。** 广场是城市原点、视野最开阔的一块，摆一圈棚子
就变成"摊位环岛"，人流要绕着走。留白是广场最好的状态，买东西往巷子、码头、
东西两岸走。

城市按"一条主街 + 三圈街区 + 一条河"的骨架分成几个市集区，每区只占一小段
（一截巷子、一段滨水步道、一个人行道）：

| 市集区 | 位置 | 特色 | 摊位数 |
|---|---|---|---|
| 雪松巷夜市 | `cedarLane` 西段两侧 | 天黑挂灯笼，烤串和算命 | 4 |
| 中巷创意街 | `alley` 靠西墙一排 | 手作、画作、独立出版 | 3 |
| 河岸东步道 | 桥东滨水步道 | 拍立得、钓具、热饮，收摊晚 | 4 |
| 码头早市 | 桥西、摩天轮以东的码头边 | 天没亮就开，鱼获和花 | 2 |
| 西岸市场 | 西岸大道西侧人行道 | 菜市气质：蔬果、干货、糖水 | 6 |
| 东岸街市 | 东岸大道西侧小广场 | 两个小游戏 + 旧书、黑胶（空地大） | 4 |

一期共 23 个摊位。分区之间隔一两百米，玩家从广场往外走会依次经过
「巷子夜市 → 滨水早市 → 西岸菜市 → 东岸街市」，而不是在喷泉边上一眼看完全城。

**摆位规则（`walkable()`）**：
- 不进车道（含 2.6m 退让）、不进楼、不下水，避让喷泉外圈、摩天轮基座；
- 让开行道树 / 路灯 / 长椅 / 花池；
- 让开 1F 店铺门前 8m——摊子不该堵在人家橱窗和门口；
- 让开步行区公告牌（`BOARD_CLEAR`，雪松步道那块）和每个区的区牌 4.2m；
- 摊与摊之间至少 5m，每个区两头留出通道。

每个区有自己的铺装、区牌（市集名 + 一句介绍）、摊与摊之间的彩旗，还配了
市集灯、长椅和花池。从街上走过来先看到区牌，再看到摊子；HUD 的地名也会切成
对应的市集名（站在西岸就显示"西岸市场"）。

**宠物图鉴亭**不在广场了：挪到河岸东步道背后的草坡（`noticeSpot(28, 61)`，朝河）。
广场旁边立亭子会把广场的视线切掉一半，而河岸本来就是遛宠物的地方，放在那儿
才和用途对得上。

### 6.3 NPC 摊位

空位由 NPC 经营，做成“体验点”，任何时候街上都是热闹的：

| 类型 | 例子 |
|---|---|
| 小游戏 | 打气球、套圈、捞金鱼（接钓鱼图鉴）、抽签算命 |
| 工具 | 拍照亭（生成分享卡片）、天气/日历、社区地图 |
| 功能 | 宠物美容（改颜色、换饰品）、钓具店、鱼市收购、口粮小卖部 |

每个区固定保留几个 NPC 摊（夜市一定有算命和烤串，码头一定有鱼摊，西岸一定有菜摊），
其余位置玩家没占就用 NPC 补。小游戏按场地分：打气球和套圈在东岸小广场（空地大，
圈甩得开），拍立得在桥东滨水（背景是河），算命在夜市，钓具在滨水。

### 6.4 加载

- 每个摊位只存摘要（主人、标题、颜色、封面缩略图），全社区加起来几十 KB。
- 按距离分级：远处只显示通用摊位模型（换个颜色）；30m 以内加载招牌和封面；点进去再拉完整内容。

### 7.4 烟花

- **只能在楼顶放**：公共天台（整栋楼住户共用）或顶层私人露台。电梯里多一个“RF”按钮。
- 每人每天 3 次，每次 30 秒。
- 同一个公共天台同一时间只放一场，其他人排队；私人露台不用排队。
- 服务端只推送给烟花周围 200m 内在线的玩家，不会全服刷屏，网络开销也小。
- 头顶显示“XX 在放烟花”。
- 节日时广场定时放一场全城烟花秀。
- 烟花样式以后可以做成收集品（比如钓到某种鱼解锁一款）。

#### 已实现（天台一期）

- 电梯面板多了 **RF** 按钮：只有住宅楼开放（河岸 / 雪松 / 北塔 / 青年公寓）。酒店和工作室的屋顶是设备层，不上人。
- 天台是一块真实平台：**电梯机房压在电梯井正上方**、女儿墙、水箱、排风管、烟花发射台。往下能看到自己这栋楼的外立面（复用街上的 `UnitShell`）和周围城市。
- 次数、片区限制在 `src/game/roof.ts`：
  - 老街区（雪松公寓）是安静区，点火直接拒绝；
  - 每天 3 轮，一轮 7 发，按本地日历跨天归零；
  - 次数存 `localStorage`（demo 不为此加表），面板和气泡上都能看到今天还剩几轮。
- 烟花和街区里那台发射台共用 `scene/Fireworks.tsx`，只是关掉了自带的发射台模型，坐标换成天台局部坐标。
- **还没做**：多人同台（需要在线同步）、节日全城烟花秀、烟花样式收集品。


### 7.5 私人影院

- 用 `<input type="file">` 读取本地视频，`VideoTexture` 播放到幕布上。**视频不离开用户电脑**：不上传、不分享，所以没有版权问题，也不占服务器带宽。
- 以后要做“和好友一起看”：两边各自打开同一部本地片子，服务端只同步播放进度。

## 8. 认领规则

| 规则 | 数值 |
|---|---|
| 每人房子数 | 1 套 |
| 普通户型 | 先到先得 |
| 稀缺户型（顶层复式、大平层、江景大户） | **安居积分门槛 + 开盘抽签** |
| 搬家 | 第一次免费、马上生效；之后每 7 天一次；家具跟着走 |
| 不活跃回收 | 第 20 天、第 27 天提醒；**第 30 天直接释放**；房里的东西进仓库，重新认领后一键恢复 |
| 酒店临时房 | 新用户自动分配一间，7 天有效；认领住宅后自动退房 |

### 8.1 安居积分

只能靠玩获得，不能用钱买：

| 行为 | 积分 |
|---|---|
| 每日签到 | +5 |
| 家里被参观（每位访客每天算一次） | +2 |
| 被留言 | +3 |
| 喂别人的宠物 | +2 |
| 摆摊一次 | +5 |
| 解锁一条图鉴 | +10 |

数值是初始值，上线后按数据调整。形成一条成长线：**先住小房 → 攒积分 → 换大房、好房**，和现实中“先租房、再买房、再换房”一样。

### 8.2 开盘

- 新楼和稀缺户型分批开放，不一次性放出全部。
- 普通户：开盘后先到先得。
- 稀缺户：积分达到门槛的人在报名期内报名，结束时抽签。比拼手速公平，开盘本身也是一次运营活动。

### 10.1 摩天轮

- **尺寸**：直径 40~50m，比多层住宅高、比高层塔楼矮，是天际线中间的一个层次。

## 11. 镜头

真实房间不大（卧室约 3.3 × 3.6m），现在的第三人称镜头容易穿墙或贴脸。一期把三种方案都做成可切换的，体验后再定默认：

| 方案 | 做法 | 优点 | 缺点 |
|---|---|---|---|
| A 剖切俯视 | 俯视角，自动隐藏挡视线的墙和天花板（类似模拟人生） | 布置家具最方便 | 沉浸感弱 |
| B 第一人称 | 室内切第一人称 | 沉浸感最强，最像“在家里” | 看不到自己的角色 |
| C 近景第三人称 | 镜头拉近，挡在中间的墙变半透明 | 和室外的体验一致 | 小房间里仍然局促 |

室内镜头最远距离一律限制在 9m，并且永远开着墙体避让（已在 `PlayerRig` 实现）。

#### 已实现（A + C，HUD 一键切换）

HUD 右上角多了一个「镜头」按钮（只在室内出现），在两种机位之间切：

- **C 近景第三人称**（默认）：和室外一致的跟随镜头，距离按房间尺寸算，最远 9m，开墙体避让。
- **A 剖切俯视**：镜头抬到墙顶之上（俯角约 53°、距离 11m），同时把天花板收掉
  （`RoomWalls` 的 `hideCeiling`），所以从上方能一眼看全整间屋子。这个模式下
  主动跳过墙体避让——否则镜头会被"避让"拽回房间里，俯视就没了。

机位状态存在 `store.indoorCam`，进出房间保持。B 第一人称没做：小户型里
第一人称最沉浸，但看不到自己的角色，和整个"社区里能看见别人"的基调冲突。

### 12.2 数据库

```sql
-- 认领与活跃
ALTER TABLE users  ADD COLUMN IF NOT EXISTS last_active_at TIMESTAMPTZ;
ALTER TABLE users  ADD COLUMN IF NOT EXISTS moved_at       TIMESTAMPTZ;
ALTER TABLE users  ADD COLUMN IF NOT EXISTS housing_points INT NOT NULL DEFAULT 0;
ALTER TABLE spaces ADD COLUMN IF NOT EXISTS claimed_at     TIMESTAMPTZ;

-- 仓库：回收或搬家时，房间布置整份存进来
CREATE TABLE IF NOT EXISTS storage (
  user_id    TEXT PRIMARY KEY REFERENCES users(id) ON DELETE CASCADE,
  layout     JSONB NOT NULL,
  art        JSONB,
  saved_at   TIMESTAMPTZ NOT NULL DEFAULT now()
);

-- 旧户号 → 新户号的映射，迁移后保留一段时间，旧链接还能跳转
CREATE TABLE IF NOT EXISTS space_redirects (
  old_id TEXT PRIMARY KEY,
  new_id TEXT NOT NULL
);
```

展示位（二期）、开盘报名（三期）、烟花事件（三期）的表在对应阶段再加。

### 12.3 迁移

1. 生成新社区的全部住宅空间（`UNIT_SEED_VERSION` 升级）。
2. **已认领的旧户**：按“同一栋楼 → 面积最接近 → 楼层最接近”映射到新户；楼不在新社区里的，映射到风格最接近的新楼。家具坐标按新旧面积等比缩放后再夹到房间范围内。写入 `space_redirects`，通知主人“你的家搬到了 XX”。
3. **未认领的旧户**：直接删除。
4. 特殊空间（`river-loft`、`sound-room`）保留原 id。

## 14. 明确不做

- **不做空楼的室内**。不能进的楼就是布景，没有门口标记。
- **不做写字楼工位**。和店铺功能重复；写字楼以后如果有玩法，方向是多人（社团、团队）。
- **一期户内不分隔墙**。
- **不做真实交易**。展示位前期只有展示、点赞、留言。
- **不上传用户的视频和音乐**。影院和唱片机只播放本地文件。

## 15. 风险

| 风险 | 处置 |
|---|---|
| 按真实尺寸，板楼变长（52~75m），社区放不下 | H1 先排布局再定尺寸；空间紧的位置用塔楼代替板楼 |
| 迁移后老用户找不到自己的家 | `space_redirects` 让旧链接跳转；登录后弹窗告知新门牌 |
| 高层塔楼 28 层 × 6 户，立面几何量大 | 立面合批；远处只画体量和窗灯；阳台几何只在 120m 内生成 |
| 小房间里的镜头体验差 | H6 三种方案并行，实测后再定 |
| 稀缺户型被早期用户占满 | 积分门槛 + 开盘抽签 + 分批开放 + 30 天回收 |
| 烟花刷屏、影响他人 | 每人每天 3 次；同一天台排队；老街区禁放；只广播 200m 内 |
