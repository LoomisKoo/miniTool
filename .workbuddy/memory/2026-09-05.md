## 拾光 v0.4：真正的三面立体盒（用户强调“还是平面的”）
- 用户明确：v0.3 仍「平面的，只是改了方块样式」，质疑是否理解微信跳一跳。
- 根因：之前只用 菱形顶面+矩形身子 的扁平剪影，无体积感、无三档明暗、且方块比例偏细长柱。
- v0.4 重画方块为**真正立体盒**：顶面平行四边形(最亮) + 正面(中) + 右侧面(最暗) 三档明暗区分体积；比例改矮（宽30~42、高46~82，高<宽，像盒子而非柱）；顶面四角按深度偏移(Dx,Dy=w*0.5)构造，底面落地阴影。小人身体改用圆角+底面弧增强体积。
- 关键认知：要“像跳一跳”必须有**可见的多个面+明暗差**，不能只靠轮廓。
- 校验：内联 JS `node --check` 通过。

## 拾光 v0.5：方块可朝前/后/左/右任意方向（修正“只能往前”）
- 用户反馈 v0.4 仍不对：微信小人可前后左右跳，我们的只能往前。
- 根因：路径生成 `prev.ang*0.7 + rand(-0.5,0.5)` 把角度持续往右(0)回正，路径单向右飘。跳跃方向本就=当前块→下一块的射线（无约束），所以是生成偏置导致。
- 改法：① 起始方块方向随机 `rand(0,2π)`；② 生成改为自由随机游走 `prev.ang + rand(-1.3,1.3)`，下一块可在任意方向，小人朝该方向跳。镜头始终跟随小人居中，向左/上跳时上一块自然移出视野，符合跳一跳“散布在2D平面、朝各方向跳”的观感。
- 校验：内联 JS `node --check` 通过。

## 拾光 v0.6：方向/相机/实心/起跳跳变/计分 五项修正
用户一次性反馈5点，逐条修：
1. **跳跃方向倒置**：投影 `SY=H*0.6+(y-camY)*PY-z` 把“远处”映射到屏幕下方。改为 `H*BASE_Y-(y-camY)*PY-z`，远处→屏幕上方；路径生成改为「朝远离镜头推进(fwd 95~215)+左右摆动(lat ±195)」，于是从下往上跳，且可偏左/偏右/正前。
2. **相机看不出相对位置**：PY 0.62→0.78（放宽纵深压缩），BASE_Y 0.60→0.64（小人下移留上方视野），AHEAD 6→8。
3. **方块不实心**：原来全用半透明白叠色像玻璃。改为**不透明实体色**：每块取 PALETTE 基色，顶面 shade(+.45)/正面本色/右侧面 shade(-.38)，三档明暗。
4. **起跳位置突变**：两个成因——① 起跳点误用方块中心，而小人停在落点(可能偏心) → 改为从小人**实际位置**起跳(origin=char.x/y)；② 蓄力压扁松手瞬间归零 → 加 `squash` 变量，蓄力跟随 charge、松手后 `squash+=(0-squash)*dt*16` 缓动回弹。
5. **计分**：微信式计分。普通落地 +1；跳中光心连击递增 gained=2*combo（+2/+4/+6…）。HUD 主数字换“分数”，落地飘 `+N`。回忆墙仍收集词(仅光心触发)用于导出分享。
- 校验：内联 JS `node --check` 通过。
