# 词卡物语 · 英语单词卡牌养成游戏（demo）

抽一个英文词，**每个字母都是一次独立随机排版**：字体、墨色、边框、纹饰、倾斜各自随机，
但由「单词 + 位置 + 稀有度」派生的种子决定，同一张卡永远长得一样（不需要存图片）。

字形轮廓从 OFL 字体预先抽成 SVG path，运行时用 SVG / Canvas `Path2D` 直接绘制，
**整个包体 150KB**，远低于小红书 10MB 上限。

## 本地预览

```bash
npm run build   # 打包到 dist/xiaohongshu
npx serve dist/xiaohongshu
```

## 打包上架

```bash
node build.mjs              # 小红书 / 抖音 / 快手 全打
node build.mjs xiaohongshu  # 只打小红书
node ../xiaohongshu/minitool-zip-builder/scripts/audit_artifact.mjs dist/xiaohongshu
```

产物：`dist/{平台}-word-card-tale.zip`（当前 ≈150KB）

## 玩法

| 环节 | 说明 |
| --- | --- |
| 抽卡 | 每天 2 组免费（每组 3 张，共 6 个新词），默写可换额外次数；稀有度权重 N 480 / R 280 / SR 160 / SSR 66 / UR 16（EX 为隐藏款 0.3%） |
| 卡面 | 字母瓦片逐字入场；稀有度越高，瓦片纹饰越密、字体越「古」 |
| 图鉴 | 96 词按稀有度排列，未抽到显示 `· · ·` |
| 存图 | Canvas `Path2D` 重绘同一套轮廓 → 900×1250 PNG，走 `writeTempFile` + `saveImageToPhotosAlbum` |

## 记忆成长与资源规划（后续开发）

核心目标是让玩家记住单词，因此**拼写行为应该直接推动单词成长**，而不是只换取一种通用货币。

### 进度模型（✅ 已实现）

每张词卡优先保留一条核心学习进度：

1. **熟练度 XP**
   - 拼写正确获得 XP。
   - 零失误、快速完成、连续复习可获得额外 XP。
   - 拼写错误仍可获得少量 XP，避免一次失误让玩家失去动力。
   - XP 达到阶段上限后，才有资格提升卡片段位。

目前不强行确定第二种消耗资源。若后续需要卡面装饰、提示或培养资源，再单独设计名称和用途，不能让它替代拼写 XP。

### 拼写次数与每日收益（✅ 已实现：5 次全额 / 6～10 次 40% / 超过 10 次不产出）

不建议限制玩家每天最多只能拼写某个单词 20 次或 30 次。学习者可能确实需要反复练习，硬限制会阻断学习行为。

推荐采用“可无限练习，但收益递减”的规则：

- 每次拼写都可以练习，也都能记录为一次学习行为。
- 每个单词每天前 5 次正确拼写，获得完整 XP。
- 第 6～10 次获得少量 XP，用于鼓励继续巩固。
- 超过 10 次不再产出资源，但仍允许练习，不让玩家被系统挡住。
- 零失误、快速完成、间隔复习可以增加额外奖励。

不要设置“总拼写不能超过 100 次”的硬上限。总次数本身不是记忆质量，连续机械点击 100 次也不代表真正掌握。

如果希望尽量减少存储字段，可以只保存每张词卡的：

```js
masteryXp: 0
```

但正式实现更推荐额外保存 `lastPracticeDay`，这样才能准确实现每日收益递减和间隔复习。若坚持只保留一个字段，则只统计总熟练度，不做每日次数限制，避免用不完整数据制造错误限制。

### 卡片成长

稀有度采用大众较熟悉的抽卡体系：

```text
N → R → SR → SSR → UR → EX
```

后续可在每个普通稀有度内增加 3 个熟练阶段：

```text
N1 → N2 → N3 → R1 → R2 → R3 → SR1 ...
```

升级规则：

- 当前阶段 XP 满后，才可进入下一阶段。
- 当前卡片的字母培养进度达到要求后，才可进行升阶。
- 升阶时如需消耗第二资源，只能作为少量辅助成本，不能替代拼写 XP。
- EX 作为隐藏款/特殊款，不参与普通稀有度的线性比较。

### 第二资源命名

“墨水”“墨痕”偏视觉主题，“精力”容易让人联想到真人体力，“研习点”又不够自然，因此暂不定名。

第一阶段可以只使用熟练度 XP；如果后续确实需要可消耗资源，再从“学分”“积学”“词印”等方向做用户测试。

## 非战斗玩法方案汇总（后续开发）

以下内容先确定产品规则，具体战斗形式暂不在此定案。

### 每日新词量（✅ 已按此实现）

- 3 张卡作为一组，而不是每天只能抽 3 个词。
- 默认每天可学习 2 组，即约 6 个新词（`FREE_PER_DAY = 2`）。
- 可根据用户选择扩展为 3 / 6 / 9 个新词。
- 抽卡优先从未见过、熟练度较低或长期未复习的词中选择。
- 已掌握的词不应继续伪装成“新词”。
- 当前 96 词仅适合 demo，正式版需要按主题扩充词包。

### 抽卡、失败与放弃（✅ 放弃/失败分支已区分）

- 抽卡：负责遇见新词，不直接代表掌握。
- 首次拼写成功：词卡进入图鉴，并开始获得熟练度 XP。
- 拼写失败或超时：本次不收入图鉴，进入残页/待复习状态（`addShard`）。
- 主动放弃：立即放回卡池，不获得 XP，也不产出残页（`quality: 'abandoned'`）。
- 倒计时飞走：本次未收服，下次抽卡仍可正常出现，出现概率不额外降低。
- 放弃或飞走不应永久占用抽卡名额，也不应让玩家失去再次学习这个词的机会。

### 复习与连续学习（✅ 复习池已实现，连续天数已计入称号）

- 复习对象来自到期复习池，而不是完全随机抽取。
- 优先复习：错误较多、熟练度较低、长期未出现的词。
- 连续学习 3 / 7 / 14 天可获得 XP 加成，最高加成需要封顶。
- 中断学习不删除已经获得的 XP。
- 长时间未复习时，单词进入“待巩固”状态，而不是直接降级。
- 重新正确拼写待巩固词时，获得额外复习奖励。

### 多轮拼写的说明（✅ 已完成：多轮不遮挡卡面）

高稀有度词卡（UR / EX）需要拼写两段，用来检验是否真的记住，而不是只看卡面抄一遍。

> 后续调整：多轮拼写**不再遮住单词**。卡面全程完整可读，只在右上角挂一个「再拼一次」小标，并把原因写进提示条。玩家不会以为卡片坏了，也不会因为看不到词而卡住。

界面提示：

- 首段：`第 1/2 段 · 照卡面拼 · 拼对即收录`
- 过渡：`第一段完成 · 接下来再拼一次 · 卡面仍然可见`
- 第二段：`第 2/2 段 · 卡面完整可见 · 再拼一次即收录`

记忆段不做任何遮挡：

- 卡牌边框、字母瓦片、音标、中文释义、属性、编号全部保持清晰。
- 不再替换成 `· · ·` 或 `?`，也不加半透明遮罩。

### 每日任务（✅ 已改为复习驱动）

每日任务不再重复发放一批随机新词，主要负责推动复习和持续学习：

- 完成若干个到期复习词。
- 连续正确拼写若干个词。
- 在限定时间内完成复习。
- 复习当天最容易出错的词。
- 完成一次学习流程或远征流程。

奖励重点是熟练度、抽卡机会、收藏内容和连续学习记录。速度可以提供小额奖励，但正确率必须比速度更重要。

### 个人称号（✅ 已实现 7 档，见 `app.js` 的 `TITLES`）

称号不只按拼写次数升级，应该综合：

- 已掌握词数。
- 复习完成率。
- 拼写正确率。
- 连续学习天数。
- 地图或地区完成度。

称号名称暂不定案。方向是更有词典、旅途和收藏感的称号，而不是普通的“学徒 / 高手 / 大师”式等级。

## 战斗中的词卡与大招（普通子弹已改为图形化）

战斗保留「每个字母对应不同弹种」的核心设定，普通子弹不显示大字母，避免高速战斗中画面拥挤、单词难以辨认。

### 词卡和字母弹

- 单词是一把完整的武器。
- 单词中的每个字母是武器内部不同类型的弹药。
- 字母弹自动按照单词顺序循环发射，玩家无需按住即可持续开火（拖动只负责走位）。
- 普通飞行物使用对应弹种的图形：
  - 穿透 → 细长针刃
  - 爆破 → 六角榴弹 + 亮核
  - 冰霜 → 六角雪花
  - 疾射 → 箭头
  - 护盾 → 光核环（不发射，直接加盾）
- 子弹命中敌人时才短暂闪现对应字母、碎裂和印章特效，制造打击感。
- 单词的长度、重复字母和字母组成影响循环方式与战斗属性。
- **战斗内不需要默写**：普攻自动连发，`齐射` 按冷却瞬发整词齐射（4.4s 起，星级提升略缩短），学习行为只放在抽卡、默写与复习里。

因此：

```text
字母决定弹种
单词决定弹种组合和循环
肉鸽强化决定最终攻击形态
```

### 大招充能（✅ 基础版已实现：词力条 + 满自动词爆）

大招不采用“每关固定使用几次”的方式，而采用独立能量条：

```text
0 / 100 → 充满后获得 1 次大招
```

能量来源：

- 普通子弹命中：少量充能。
- 击杀敌人：中量充能。
- 完整发射一轮单词：大量充能。
- 击败精英或首领：额外充能。
- 肉鸽强化：提高充能效率或增加储存上限。

大招最多储存 2 次，避免能量溢出。普通战斗房间目标为释放 1 次大招，构筑成型后可以释放 2 次。

### 大招和单词的关系

大招不统一做成“全屏炸弹”，而是根据词卡的弹种构成生成不同的终结效果：

- 散射倾向：单词聚合后爆炸，形成环形或多段范围冲击。
- 穿透倾向：字母排列成巨大词刃，贯穿整条战场。
- 减速倾向：形成冻结词阵，使敌人减速或短暂冻结。
- 追踪倾向：单词拆成多个光点，自动追踪敌人。
- 护盾倾向：形成词环圣域，抵挡攻击并在结束时反击。

大招变化规则：

- 单词长度决定释放阶段数、持续时间和演出规模，不直接决定绝对强度。
- 重复字母触发回响、复制、追加爆炸或镜像效果。
- 稀有度决定大招的强化槽数量和视觉上限。

### 大招表现节奏

每次大招分为四个阶段：

1. 聚词：单词或字母短暂聚集。
2. 蓄力：背景压暗、光线集中，制造预兆。
3. 爆发：范围攻击、冲击波、白闪、屏幕震动和敌人受击反馈。
4. 余韵：字母碎片、残影和光效渐隐。

完整单词只在大招、强攻击或关键节点出现，不作为普通子弹持续显示。

### 开局体验

玩家第一次进入战斗时，不应从完全没有能力的状态开始：

- 初始大招能量可以从 50% 开始。
- 第一波结束后保证获得一次大招。
- 首次战斗必须让玩家看到完整词卡终结技。

后续再通过路线选择、肉鸽强化和词卡组合逐步扩大范围、伤害、穿透、追踪和连锁效果。

## 地区与食物资源方案（部分完成：地区选择与首领命名已上线，像素食物美术待做）

地区敌人可以使用真实食物作为文化内容，但食物是地区收藏品和词汇载体，不代表某个国家或人群是敌人。

### 资源表现

不追求照片级写实，优先保证食物的识别度和层次：

1. 轮廓层：让玩家一眼识别贝果、拉面、饭团、可颂等食物。
2. 细节层：保留芝麻、海苔、面条、奶油、酱汁等 3～5 个关键特征。
3. 游戏层：加入发光字母、错误裂缝、蒸汽、像素碎片和受击效果。

推荐使用：

```text
低分辨率像素结构 + 矢量化轮廓 + Canvas 动态特效
```

### 数据化资源

像素食物不强制保存为 PNG，可以使用 JSON 定义：

```js
{
  grid: 24,
  palette: ['#3a241b', '#d79b52', '#f3d28b'],
  layers: [
    { cells: '...' },
    { cells: '...' }
  ]
}
```

矢量食物也可以用数据层描述：

```text
主体轮廓
阴影层
高光层
装饰层
字母污染层
```

运行时由 Canvas 或 SVG 渲染，再用程序化粒子完成爆炸、碎裂、发光和蒸汽动画。

### 资源制作原则

- AI 图片只作为概念参考，不直接大量放入最终包体。
- 普通食物优先使用 24×24 或 32×32 像素结构。
- 首领和重要食物可以使用更复杂的 SVG 或多层数据。
- 每个地区使用 3～5 个文化视觉元素，不为每个敌人制作一套完整图片。
- 通过颜色、配料、装饰和场景区分地区，避免重复绘制。
- 食物名称、来源地区和简单介绍可以进入文化图鉴。

这种方案可以同时满足真实食物的辨识度、像素或矢量风格、动态战斗效果和小红书 10MB 包体限制。
