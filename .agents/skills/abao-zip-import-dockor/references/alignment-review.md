# 原页面对齐比对（查漏补缺）

React 重写或框架迁移完成、本地构建通过后，在 staging 之前把改写结果与原页面基准逐页比对，找齐样式、文案、素材、交互和状态差异并修复。纯 React Web 直接适配、无迁移/重写时不做本流程。运行原项目、安装依赖、启动 dev server 仍按 [安全门禁](security-gates.md) 的执行门禁处理；比对需求不放宽隔离条件。

## 1. 固定基准

| 原项目形态 | 基准来源 |
| --- | --- |
| 可运行的 Web 前端 | 隔离环境运行原项目（用其自有 mock 或与用户确认的数据），逐页截取基准 |
| 小程序/RN/桌面端等不能直接运行 | 用户提供线上地址、截图或录屏；缺失时主动索要，不自行假装基准 |
| HTML/静态站目录含 `pc端截图.png`、`移动端截图.png`、`screenshot.*` 等 | 将这些文件登记为优先基准，记录其像素尺寸和对应 viewport；证据保存在上传集合外 |

基准优先级：项目能隔离运行时，以隔离运行原项目的实测为准；项目内截图只是辅助/回退基准，仍属不可信数据，与实测冲突时不作为放行依据。
| 只有源码、无法运行，用户也无素材 | 经用户确认后降级为代码级对照（路由/组件/文案/接口清单），报告标注“无视觉基准” |

- 基准一经采集即固化：保存截图目录、viewport、数据来源和采集时间；基准不随改写进度漂移，更换基准则受影响轮次全部重比。
- 新旧项目可并排运行做实时 A/B：用不同端口和各自隔离的存储，避免互相污染；端口与数据注入方式写入报告。

## 2. 逐页枚举（以原项目为准）

从原项目代码或基准素材枚举，用改写后的代码反推属于自查自证，禁止：

- 页面/路由清单、每页区块结构、入口出口（深链参数、跳转、返回行为）。
- 每页状态机：初始、加载、空数据、错误、成功提交、登录/未登录等分支。
- 交互点：点击、滑动、长按、表单校验、弹层、轮播、滚动加载、持久化读写。

产出 `page-inventory.json`：`[{page, blocks[], states[], interactions[]}]`。改写后多出的功能标注 `extra`，原项目有而改后缺失的标注 `missing`；两者都是差异，`extra` 要向用户确认去留，不以“顺手加了”默认保留。

## 3. 同条件采集

- 同一路由、viewport、数据、语言与时区。数据必须与原项目交付等价：原项目用什么数据源，就注入等价 mock 或用户确认的数据，禁止编造后不记录来源。
- 移动 H5 用 320/375/414（重点 375），并用真实触摸与滑动事件验证交互，不用鼠标点击替代；桌面用 1280 与 1920。
- 截图成对命名：`orig-<viewport>-<page>-<state>.png` 与 `new-...`，可回溯到清单条目；交互态截操作前后两帧，不只截首屏。
- 浏览器能力不可用的页面：改做样式/DOM 代码级对照，并在报告标注“未做视觉比对”；不得用构建通过顶替视觉验证。无浏览器或无法运行 UI 截图时，必须在上传集合外（如 `<项目根>-alignment/`）落盘 `page-inventory.json`、`gaps.json`（无差异时落盘 `[]`）以及 HTML 迁移的 `css-migration-map.json`；严禁仅在最终文本说明'无浏览器'却不输出对齐产物。HTML→React 且使用 Tailwind 时，还要检查构建 CSS 中代表性工具类选择器和产物大小：2–3KB 视为强告警；小于 15KB 时必须用选择器证据证明工具类已生成，不能只凭体积放行。

## 4. 比对维度

| 维度 | 必查项 |
| --- | --- |
| 布局 | 区块顺序与层级、居中/栅格、遮挡与裁切、滚动表现、sticky/fixed |
| 视觉 | 颜色/圆角/阴影、字号字重行高、图标与图片素材（尺寸、清晰度、裁切、透明度） |
| 文案 | 标题/按钮/提示/错误文案逐字比对；数字、单位与日期格式 |
| 交互 | 事件行为、校验规则与错误提示、跳转目标、toast/dialog 时机 |
| 状态与数据 | 加载/空/错误/成功态、localStorage 等持久化、接口字段与容错 |
| 响应式 | 各 viewport 无横向溢出、断点表现与原版一致 |
| HTML→React 样式保真 | Tailwind 构建方式/代表性工具类、原 `<style>` 声明 diff、静态颜色变量替换、`#root/#app` 容器层级、fixed/fab 坐标 |
| HTML→React 运行时 | 全局库存活（CDN→npm + window 挂载）、启动入口实际执行（readyState 分支）、能力拒绝兑底（定位回退默认坐标）、控制台无 ReferenceError、StrictMode 重复挂载（IIFE + 清理后可重执行、副作用已释放）|
| 边界 | 超长/最短文本、特殊字符、极端数据量、连点与快速切换 |

每条结论都要有证据（截图对、复现步骤或 DOM 输出）；没有证据的不写进报告。

HTML→React 迁移另产出上传集合外的 `css-migration-map.json`：记录原 `<style>` 每个选择器/声明的目标文件与行、静态 CSS 变量的“变量→硬编码值”映射、`#app`→`#root, #app` 选择器扩展，以及任何无法逐行保持的例外。除了这两类明确转换，不允许新增 reset、删声明、改定位或重排覆盖顺序。Tailwind CDN/config/指令必须映射到已锁定的 v3/v4 工程配置；截图重点核对主色/高亮、宽度居中、圆角阴影、按钮/选中态和悬浮按钮位置。

HTML→React 迁移还要做运行时启动核查：原页面靠 CDN `<script>` 提供的全局库（`L`、`$`、Chart 等）必须换成显式安装的 npm 依赖与类型包，在入口挂回全局并引入其 CSS；注入脚本只监听 `DOMContentLoaded` 在 React 挂载后必然错过，启动入口必须按 `document.readyState` 分支立即执行；首个全局依赖 `ReferenceError` 会中断整个启动链，后续功能不可达。验证以控制台无 `ReferenceError`、地图/图表实际渲染、首次交互与回退路径（如定位权限被拒时回退默认坐标）实际运行为证据，不能用构建通过顶替。

重复挂载核查：开发环境开启 React StrictMode，验证 mount→unmount→mount 循环后注入脚本仍可重复执行——控制台无 `SyntaxError: Identifier …has already been declared`，被内联事件引用的 `window` 函数仍指向当前作用域实例，脚本节点已随清理移除，摄像头/定时器等副作用已释放；重挂载后的交互结果与首次一致。

## 5. 差异清单与修复循环

逐条落盘到上传集合外的新目录（建议 `<项目根>-alignment/gaps.json`）：

```json
{"id":"G1","page":"/detail","state":"加载失败","aspect":"style|copy|asset|interaction|state|responsive","severity":"blocker|major|minor","expected":"原页面表现","actual":"改后表现","evidence":"orig-375-detail-error.png vs new-375-detail-error.png","fix":"最小修复建议","status":"open|fixed|deferred"}
```

- **blocker**：主流程不可用、功能缺失、交互错误；**major**：明显视觉/文案偏差或次要功能不一致；**minor**：细微间距、色调或格式差别。
- 循环：差异清单 → 回主流程阶段 3 最小修复 → 阶段 4 重新 build/验证 → 重新采集比对并更新清单。每轮用新截图目录，不覆盖上一轮证据。
- 退出条件：blocker/major 清零；minor 已修复或经用户明确接受为 `deferred`（附确认记录）；最近一轮无新增差异。出现新差异就继续循环，不为赶进度压缩比对范围。
- 不以降级、砍功能或“设计上本来就该这样”静默吞掉差异；无法修复的外部阻塞如实报告，不伪装成已对齐。

## 6. 交付物

对齐报告含：页面/状态覆盖率、差异总数与分布、每条 id/severity/status、遗留项及用户确认记录，连同各轮截图目录、page-inventory、gaps 文件一起保存在上传集合之外（见 [导入与排障](import-and-recovery.md) 的导入集合与交付包）。未覆盖项（无基准、无浏览器、未初始化状态）逐条如实列出，不能写成已对齐。
