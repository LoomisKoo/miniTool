# 高质量人生指南

把开源项目 [《高性价比人生指南》](https://github.com/eternity4719/HowToLiveBetter)（CC BY 4.0，34 节 765 条）
编译成一个**单文件、离线可用**的移动端查询工具。双击 `index.html` 即可，不需要服务器、不需要联网、不需要账号。

原文是 GitHub 上的 Markdown 文档仓库（同时提供 PDF、EPUB、Anki 和在线检索页），不是出版书。本工具是它的衍生版本，只多做了场景索引、搜索筛选和收藏。

## 产物

`index.html` —— 约 4 MB，HTML/CSS/JS 和全部 765 条正文都内联在里面，可以直接丢进 QMuse 之类的平台。

## 三个页签

| 页签 | 内容 |
| --- | --- |
| **首页** | 「按场景」27 个生活场景（在家、突然出事、看病、被裁、租房…）／「按章节」原文 34 节。顶部的模式切换 tab 吸顶 |
| **精选** | 今日精选（默认同日固定一条，「随机」在模块内切换；收藏星在右侧）、省力清单、结论最硬的（A）、有争议的 |
| **收藏** | 收藏列表（无页内大标题） |

全局搜索（标题、说人话、收益、来源、备注都可搜）、筛选抽屉（证据等级 / 性价比 / 换回什么 / 花钱 / 花时间 / 要毅力 / 争议 / 待核实）、
条目间「见第 X 节第 Y 条」可点开就地查看、统计术语（HR、RR、MET、LDL…）带悬浮解释、点卡片展开原始数字，出处收成一个「来源」按钮。

## 交互与动效

**页面转场是 iOS 式右进右出**：推进（进章节、进场景）时新页从右侧滑入、旧页左移 30%；返回时完全反向
（从哪进就从哪出，`apple-design` 的空间一致性）。**页签切换不滑动，只做 150ms 交叉淡入**——三个页签是平级关系，
不是层级关系，滑动会传达错误的空间模型。

位移转场全程 `opacity` 保持 1，不压暗离场页：两个页面都是不透明全屏层，一旦压暗，下层页面的字就会透上来，
看起来像两页文字互相穿插。层叠顺序显式指定（推进／淡入新页在上，返回时退场的旧页在上），不依赖 DOM 顺序。

**详情里的「来源」收成一个按钮**：原始出处是一整段 400 字上下、最多十几个链接的引用，铺在详情里没人看。
小工具里不能开外链：底栏 **来源**（单链复制 / 多链抽屉）与 **分享** 并排；抽屉里点整行复制。
无外链的法规类引用仍在面板内平铺「来源」正文。不显示「第 X 节第 Y 条 · 章节名」脚注。
只有 5 条法规类引用没有任何外链，照旧平铺——没有可跳的目标时，平铺才不会丢内容。

**卡片展开用 `grid-template-rows: 0fr → 1fr`**，不用 `height`，也不需要 JS 量高度，收起时高度精确回到 0。
详情区外面多包一层 `.detail-inner`（`overflow:hidden; min-height:0`）作为裁切层。

**首页的「按场景 / 按章节」tab 吸顶**（`.segwrap`）：它是下方列表的控制项，滚走之后就没法切模式了。

**底部三个页签的高亮 = 当前所在分区**，由 `syncTabs()` 统一驱动，挂在 `transitionTo()` 里，所以每次导航（含返回）都会重新同步。
在列表页里也保持高亮，因为还属于那个分区。选中态是图标恢复彩色 + 放大 1.12 + 文字转强调色加粗。

曲线和时间全部取自 `animate` skill 的表，没有手搓：

| 用途 | 值 |
| --- | --- |
| 推进／返回（层级导航） | `cubic-bezier(0.32, 0.72, 0, 1)`（iOS 抽屉曲线），340ms |
| 页签交叉淡入 | `ease`，150ms |
| 卡片展开／收起 | `cubic-bezier(0.23, 1, 0.32, 1)`，320ms |
| 按压反馈 | `cubic-bezier(0.23, 1, 0.32, 1)`，120ms |

**只有这些会动**：转场、展开、按压。列表内容不做逐个淡入、不做错峰入场——列表在页签切换时会反复出现，
按 `animate` 的频次门禁（每天数十次 → 只能近乎察觉不到），加了就是噪音。

转场期间**不锁输入**：连续快点时 `flush()` 会立刻把上一段动画收尾，从当前位置接着跑，不会排队等。

## 移动端适配

按 `mobile-native` skill 的基线做的：

- `viewport-fit=cover` + `interactive-widget=resizes-content`，**没有 `maximum-scale=1`**（那会禁掉缩放；
  输入框字号已经设成 16px，才是防 iOS 自动放大的正确做法）
- `theme-color` 分浅色／深色两档，`color-scheme: light dark`，深色模式整套配色都调过
- `100dvh` 而不是 `100vh`（地址栏收起时不会多出一截）
- `env(safe-area-inset-*)` 处理刘海和底部横条；`tools/pack.mjs` 打小红书包时给 `<html>` 写死 `env-xhs`（`--nav-h:44px`，与其他工具一致，不做运行时检测），顶栏/无搜索顶栏页用 `--xhs-nav`（`safe-t + nav-h`）避让系统导航
- 全局 `-webkit-tap-highlight-color: transparent`；每个可点元素都有 `:active` 反馈（按下 `scale(.96)` 左右）
- `touch-action: manipulation` + 控件上 `user-select: none`（去掉 300ms 点击延迟、长按不选中按钮文字）
- 根容器 `overscroll-behavior: none`，滚动容器 `contain`（不触发下拉刷新、滑动不穿透）
- 横向滚动条 `touch-action: pan-y`
- 全项目**没有一条 `:hover` 规则**，所以不存在触摸端悬停态粘住的问题

## 架构

`body` 是一个 `height:100dvh; overflow:hidden` 的弹性列：顶栏 / 页面栈 / 底部页签。**整页不滚动，滚动交给每个 `.page`**，
每个页面因此有自己的滚动位置（转场时会记住并恢复）。

`#stack` 里是**两个叠放的页面层**，转场时一层进一层出，动画结束后把退场那层清空并隐藏。
`frontIdx` 指向当前层；收尾统一走幂等的 `finishTx()`（定时器和快速连点时的 `flush()` 都调它），
所以一段动画只会收尾一次——收尾跑两次会把 `frontIdx` 翻转两遍，两页就都留在可见状态。

渲染进第二层之前必须先取消它的 `hidden` 再赋 `scrollTop`：`display:none` 时赋 `scrollTop` 会被浏览器忽略，
返回长列表时滚动位置就是这么丢的。

顶栏里的搜索框是**常驻的真实 `<input>`，永远不会被重绘**——所以中文输入法不会被打断（之前每敲一个字就整体重渲一次
`<input>`，拼音会被截断）。它也不再和页面内的第二个搜索框重复。

## 重新生成

```bash
node tools/build.mjs                                  # 自动找原文，没有就克隆到 ../.cache/
node tools/build.mjs --src /path/to/HowToLiveBetter   # 指定本地原文目录
```

脚本会：

1. 解析 `book/*.md`，抽出每条的成本 / 说人话 / 收益 / 证据等级 / 来源 / 备注，以及 `<!-- 成本标签: … -->` 里的成本与收益量级；
2. 按原书口径算性价比（收益「大」且三项成本全为 0 → 极高；成本合计 ≤2 → 高；收益「中」且成本全 0 → 高；其余一般）；
3. 用 `tools/scenarios.mjs` 的关键词把条目归类到场景；
4. 把数据内联进 `tools/template.html`，输出 `index.html`。

跑完会打印节数、条数、证据等级分布、性价比分布、每个场景的条数，以及**有问题的条目**（缺字段、关键词一条都没命中的行）。
数字和原文一致时说明解析没问题：765 条、A 495 / B 218 / C 52、极高 122 / 高 344 / 一般 299。

## 调场景分类

场景分类是纯关键词的，写在 `tools/scenarios.mjs`：

- `SEC_DEFAULT`：每一节的默认场景，保证 765 条每条都落进至少一个场景；
- `SCENARIOS[].keys`：正则数组，**只匹配标题和「说人话」两段**（收益 / 来源字段太长、词太泛，匹配它们会大量误伤）；
- 一条建议可以同时属于多个场景。

改完重跑 `node tools/build.mjs`，几秒钟出新结果，不用手工标注。
工具界面里点进任意场景，每张卡下面会显示**「命中关键词：…」**，一眼能看出为什么归到这里；
显示「所属章节：第 N 节」的说明它是靠默认场景进来的，不是关键词命中的。

`tools/data.json` 是构建时的中间产物（含每条命中原因），方便用 `node -e` 抽查归类，不纳入版本管理。

## 打包

```bash
node tools/pack.mjs                # 默认小红书 → dist/xiaohongshu-life-guide.zip
node tools/pack.mjs kuaishou       # 快手 → dist/kuaishou-life-guide.zip（单文件，≤8MB）
node tools/pack.mjs xiaohongshu kuaishou
```

小红书：容器 CSP 禁止内联脚本，把 `<script>` 拆成 `app.js`，并给 `<html>` 写死 `env-xhs`。  
快手：无容器顶栏，`--safe-t` / `--nav-h` 置 0，保持单文件内联。两边都去掉 base64 favicon。

## 自检

```bash
node tools/smoke.mjs
```

用最小 DOM 桩把 `index.html` 的渲染路径真跑一遍（37 项）：765 条是否都能渲染成卡片、每一节计数是否合计条目总数、
所有「见第 X 节第 Y 条」引用是否都指向存在的条目、27 个场景是否有空场景、搜索是否会抛错、
**收藏页是否无多余标题区**（防回归）、**详情区内容是否都在 `.detail-inner` 里**（展开动画的裁切层，
内容漏在外面动画就会裁错），以及两组回归断言：**转场中两页是否全程不透明、结束后是否只剩一页可见**（遮挡与重影）、
**来源是否都折叠成复制按钮且外链都是 http(s)**。`node --check` 抓不到的运行期问题靠这个兜。

桩本身也要求说真话：`URL` 必须能真解析（否则 `hostOf` 的 `try/catch` 会吞掉一切，断言永远绿）、
元素 `hidden` 时赋 `scrollTop` 必须被忽略（照抄浏览器的行为）。桩比真浏览器宽松，测试就会假绿。
