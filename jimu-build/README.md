# 积木搭建（jimu-build）

真 3D 积木拼搭小工具。触摸旋转视角、点一下落砖、可以往上叠、能选中已放的砖旋转/删除，场地还能按边加宽，最后导出作品卡。

> **命名注意**：本工具刻意使用「积木 / 颗粒 / 砖」这类通用词，**不使用任何品牌名**。
> 带凸点的互锁砖其原始专利早已过期，且「砖的形状是纯功能性设计、不能作为商标」（欧盟法院 2010 年判决），
> 所以通用零件本身可用；但品牌文字、标志、小人仔、授权主题与具体套装复刻均不可使用。
> 新增文案时请沿用中性词，也不要写「兼容某品牌」这类表述。

## 为什么「通用零件」很省

整份代码只有 **7 种规格**的砖（`1x1 / 1x2 / 1x3 / 1x4 / 2x2 / 2x4 / 2x6`），每种只是一个 `{w, d}` 数字：

```js
var BRICKS = [
  { id: '1x1', w: 1, d: 1 },
  { id: '2x4', w: 4, d: 2 }
];
```

凸点、砖体、颜色全部程序化生成，**没有任何模型文件、贴图、PNG**。

## 凸点（正反面）的几何

这是最容易做错的地方。凸点必须长在砖体**顶面之上**，否则会被埋进砖体里、什么都看不见：

| 量 | 值 | 说明 |
|----|----|------|
| `BRICK_H` | 1.2 | 一层砖高（= 3 块薄板） |
| `SEAM` | 0.014 | 砖体上下留缝，避免共面 z-fighting，也读作砖缝 |
| `BODY_H` | `BRICK_H - SEAM` | 砖体高，**顶面正好落在层顶** |
| `STUD_R` / `STUD_H` | 0.30 / 0.16 | 凸点半径 / 高（0.30 是通用积木的比例） |
| `STUD_EMBED` | 0.012 | 凸点根部埋进砖体一点，避免出现缝隙 |
| `STUD_Y` | `SEAM + BODY_H - STUD_EMBED + STUD_H/2` | 凸点中心（相对层底） |

算出来砖体范围 `[0.014, 1.200]`、凸点范围 `[1.188, 1.348]`，即：

- 凸点**露出砖体顶面 0.148** → 顶层砖的凸点清晰可见
- 叠放时凸点落在上层砖体 `[1.214, 2.400]` 内部 → 被包住看不见

这正是真实积木的行为：凸点只在最上层露出来，砖缝处只留一圈 0.014 的细环。

## 选中 / 旋转 / 删除

- 点砖的**顶面** = 往上叠一块
- 点砖的**侧面** = 选中（黄色描边，`depthTest: false`，被挡住也看得见）
- 底部出现操作条：`旋转` / `删除` / `取消`
- `旋转` 会自动**找位并保持重心**：在 ±3 格范围内搜索第一个合法落点，代价最小的优先
- 旋转/删除都是**原子**的：空间不够或上方压着砖时整条操作放弃，状态不变，只弹提示
- 拦两件事：上方压着砖不能转/不能拆（否则上层会悬空）

## 场地加宽

HUD「场地」打开一个十字面板，点任一 `＋` 给该边加 **30** 格。

| 项 | 值 |
|----|----|
| 默认场地 | **50 × 50** |
| 单边上限 | **300** |
| 每次加宽 | **30** |

逻辑格坐标允许为负（`board.x0` 可以小于 0），所以负方向扩出来的区域能正常落砖。加宽会卡住上限，并且能刚好顶到 300（`300 = 50 + 30×8 + 10` 这种余数也能补齐）。

## 尺寸调大后连带处理的三件事

把上限从 32 提到 300 会撞到几个硬限制，都已处理：

### 1. 底板凸点的性能闸门

300×300 = **90000** 个底板凸点，每个 24 个三角面就是 216 万三角面 —— 而且那时每格只有约 2px，凸点只是看不见的碎点。

所以超过 `BASE_STUD_CELL_MAX = 25000`（≈158×158）就**不再画底板凸点**，底板变成光板：

| 场地 | 底板凸点 | 三角面 | draw call |
|------|---------|--------|-----------|
| 50×50 | 2500 | 60,012 | 2 |
| 140×140 | 19600 | 470,412 | 2 |
| 170×170 以上 | 0 | 12 | 1 |

闸门值可调。调大的代价是三角面线性增长。底板凸点用 6 边形（不是砖上凸点的 12 边形）也是同一个原因。

### 2. 相机近/远平面

场地跨 300 格时，`far` 必须够远才不会把场地切掉；但用户又能凑近看单块砖，`near` 又不能太大。所以两者都跟着相机距离走，并且**在每次相机变更时重算**（不能只在取景时算一次，否则从大场地放大进来会被裁切）：

```js
camera.near = Math.max(0.5, cam.dist * 0.01);
camera.far  = cam.dist * 2.5 + Math.max(boardW(), boardD()) * 2 + 300;
```

### 3. 阴影自动关闭

阴影相机的覆盖范围是 `场地 × 0.8 + 8`，场地一大会导致 1024 的阴影贴图覆盖几百格，阴影糊成一片还白费一次 draw pass。所以场地单边 > 150 时直接关掉：

```js
keyLight.castShadow = big <= 150;   // 改 castShadow 会自动触发着色器重建
```

## 省资源的三个关键

| 手段 | 说明 |
|------|------|
| 3 个 `InstancedMesh` 承载全部 | 砖体一个、砖上凸点一个、底板凸点一个。上千块砖也只有 2~3 个 draw call |
| 逻辑用体素网格 | `occ["x,y,z"]` 字典判占用，堆叠靠查表，**不上物理引擎** |
| 按需渲染 | 只有改动或落砖动画时才 `render()`，静止时零耗电 |
| 底板凸点按需分配 | 容量按当前场地惰性分配，不是一上来就开 90000 个槽位 |

## 两个踩过的坑（已修，别改回去）

### 1. `InstancedMesh` 的包围球是缓存的

`InstancedMesh.raycast` 会先拿 `this.boundingSphere` 粗筛，而这个球**只在第一次射线检测时算一次**。实例为空时算出来半径是 `-1`（哨兵值），之后所有射线检测都会被直接否决 —— 表现就是**所有砖都点不中**。

所以 `addBrick` / `removeBrick` 里必须作废它：

```js
bodyIM.boundingSphere = null;   // 实例集合变了，缓存球必须作废
```

### 2. 实例槽位必须连续

槽位就是 `bricks` 的下标，删除时用「末尾换位」保持连续，这样 `count === bricks.length`，包围球才是紧的、射线检测才是准的：

```js
var last = bricks.pop();
if (last !== b) { bricks[idx] = last; last.slot = idx; layout(last, 0); paint(last); }
```

### 3. 清空要绕开「上层保护」

`removeBrick` 有「上方压着砖不许拆」的保护。清空如果直接遍历调用，**只有最上层会被清掉**。清空必须自上而下 + 强制：

```js
var list = bricks.slice().sort(function (a, b) { return b.y - a.y; });
for (var i = 0; i < list.length; i++) removeBrick(list[i], false, true);
```

## 结构

```
jimu-build/
├── index.html            # 生成物，勿手改（由 build.mjs 从 src/body.html 生成）
├── build.mjs             # 生成 index.html + 打包平台 zip
├── src/
│   ├── body.html         # 页面结构（唯一数据源）
│   ├── style.css         # 含平台差异化变量 --safe-t；--dock-h 由 JS 实测写入
│   └── app.js            # 场景 / 体素逻辑 / 触摸 / 选中 / 场地 / 导出
├── vendor/three.min.js   # r160，离线内置
├── platforms/{xiaohongshu,kuaishou}/config.json
└── assets/icon.jpg       # 可选，没有则产物不含图标
```

## 命令

```bash
node build.mjs dev                  # 只生成 index.html
python3 -m http.server 8000         # 然后打开 http://localhost:8000
node build.mjs                      # 打包全部平台
node build.mjs xiaohongshu          # 只打小红书
```

产物在 `dist/<平台>/` 与 `dist/<平台>-jimu-build.zip`（限制 8MB）。
小红书产物会校验：无外链、无 CDN、无内联 `script`、无 HTML 内联事件。

## 操作

| 手势 | 行为 |
|------|------|
| **单指轻点** | 落砖 / 选中（绝不转视角） |
| **双指拖动** | 旋转视角 |
| **双指 pinch** / 滚轮 | 缩放 |
| 右键拖 / Alt+拖（桌面） | 旋转视角 |
| 「换向」按钮 | 只改下一块砖的朝向（0°/90°/180°/270°） |
| HUD「场地」→ `＋` | 给该边加宽 30 格 |
| 撤销 / 清空 | 清空需要按两次（webview 里 `confirm` 常被拦） |

> 手势冲突的根因：旧版「单指拖动超过 10px 就转视角」，轻点落砖很容易被误判。
> 现已彻底拆开 —— 单指只管摆，双指才转视角。

放置规则：不越出场地、不重叠；第 2 层以上**至少一格有支撑**即可（允许悬挑）。

相机默认 `yaw 0.72 / pitch 0.78`，`fitCamera()` 会按场地大小和屏幕宽高比自动取景（竖屏时横向是瓶颈）。实测 50×50 时底板横占 94%、纵占 51%，300×300 时横占 97%，都不被底部工具条遮挡。

## 还没做的（后续可选）

- 撤销不记录「换色 / 旋转 / 场地加宽」
- 无音效
- 刷新即清空，没做持久化
- 旋转时如果上方压着砖会直接拦掉，没有「连带上层一起转」
- 场地大于 `BASE_STUD_CELL_MAX` 后底板没有凸点（性能取舍，见上）
- 没有平移视角，场地拉很大后想看清某个角只能靠缩放
- `assets/icon.jpg` 为空时产物不含图标
