## 1. 结论先行

| 决策 | 内容 |
| --- | --- |
| 收费模式 | **一次性买断（非消耗型 IAP）**，不做订阅 |
| 开通范围 | 仅 iOS App（走 Apple IAP）。H5 端（小红书 / 抖音 / 快手）**保持全免费**，见 §9 |
| 商品 | 1 个：`com.deernames.pro.lifetime` |
| 建议定价 | ¥38 终身，首发 ¥25（≥2 周） |
| 家庭共享 | **开启**（Family Sharing），取名类 app 家庭传播强 |
| 权威入口 | 「我的」页置顶 Pro 卡片 + 各付费墙弹层内 |
| 核心理念 | 免费线给完整体验，Pro 锁「量」与「深度」；**新增旗舰功能**（昵称 / 读音 / 家族档案）是主要付费理由，锁现有能力是辅助 |

### 为什么买断而不是订阅

1. **需求一次性**：取名集中在孕期 ~ 出生后 1~2 个月，用户生命周期短，订阅必然产生大量「付了钱只用三次」的差评与退款。
2. **无持续成本**：纯离线工具（无服务器、无 AI 调用），按月的收费理由站不住脚。
3. **买断转化更高、口碑更稳**，适合首发表单优惠。
4. **代价**：买断必须「一次给足」，所以上架前权益包要够厚 —— 这是本文档存在的理由。

对照 `naming/README.md` 与 `DeerNames/` 代码：

| 现状 | 问题 |
| --- | --- |
| 无任何内购代码（无 StoreKit / entitlement） | 从零开始 |

| 只有单个名字，无家庭 / 对比 / 报告 | 缺「一眼值钱」的重功能 |

**关键判断**：单纯锁现有功能不足以支撑买断 —— 用户会觉得「你把本来就有的东西藏起来了」。必须**先加高价值新功能**，再把新功能 + 部分「量」一起放进 Pro。

## 4. 新增功能规格

### 4.1 小名 / 昵称 🆕（优先级 P0，ROI 最高）

**为什么先做**：它是「取名之后的第二次消费」，天然延长生命周期；与大名/英文名同一条价值链，**完全复用现有 7 维引擎与收藏体系**，投入小。

**数据层**
- 文件：`src/data/nicks.js`（H5）/ `ios/.../Resources/Data/nicks.json`（iOS）
- 结构：
  ```json
  {
    "n": "雯雯",
    "from": "晓雯",
    "type": "叠字",
    "tag": ["亲昵", "可爱"],
    "g": "f",
    "m": "叠字小名，柔软亲昵",
    "en": "Wenwen"
  }
  ```
- `type`：叠字 / 小X / X儿 / 阿X / 单字回读 / 精选
- `tag`：亲昵 · 可爱 · 文雅 · 中性 · 方言感 · 洋气 · 传统
- 目标规模：精选库 300+ 条，派生规则覆盖全部名字

**引擎层（`NickEngine`）**
- 派生规则（无需数据，纯算法）：
  - 叠字：名末字叠（晓雯 → 雯雯）
  - 小 + X：小 + 名首字（晓雯 → 小晓）
  - X + 儿：名末字 + 儿（带儿化，标「北方语感」）
  - 阿 + X：阿 + 姓首字或名首字（标「南方方言感」）
  - 单字回读：取名中意象最柔的字
- 排序：复用 `scoreVector` —— 昵称取字的向量与 `profile` 算余弦，**按性格排**（与大名同一把尺子）
- 过滤：复用 `blacklist` / `validate`（谐音、拗口、声调）

**UI**
- 入口：详情页新增 pill「小名昵称」（`DetailView.swift` 的 pill 行）
- 新页面 `NickView`：顶部筛选（分类 tag / 亲昵度 / 单双字 / 性别），列表 + 收藏
- 卡片：新增「大名 + 小名」双行版式（复用 `NamingShareCard`）
- 收藏：`FavItem.kind` 增加 `"nick"` 分支，`surnameOfFull` 逻辑复用

**英文昵称**：`NMEnName.nick` 已有昵称链，中文小名与英文 nick 做一张对照卡（「中文小名 ⇄ 英文昵称」）。

### 4.2 读音体检 + 试听 🆕（优先级 P1）

**核心洞察**：纯 TTS 不值钱（系统朗读可替代）。真正的痛点是**多音字** —— 「茜、柏、乐、行、予、诺」在名字里读什么，老师/护士/同学经常念错。

**实现**
- 多音字表：`polyphones.json` → `{ "茜": { "name": "qiàn", "alt": "xī" } }`
  - 复用字库已有 `py` 数据，只补多音字与名字中惯读的判定
- 朗读：`AVSpeechSynthesizer`，离线免费，三种音：`zh-CN`（普）/ `yue-HK`（粤）/ `en-US`
- 声调走势：把 `tones` 画成一条走势条（复用 `WxBarsView` 的绘制风格）
- 连读警示：复用现有 `Readability`（三声连读、声调全同、音节重复）
- 卡片：Pro 卡片上带拼音 + 声调标注，可分享给长辈

### 4.3 家族档案 🆕（优先级 P2）

- 模型 `FamilyProfile`：多个宝宝档案（性别 / 生辰 / 已有名）、双胞胎 / 情侣 / 一家三口
- 卡片：「一家三口」「双胞胎」合集版式（README 已列此缺口）
- 存储：`UserDefaults`，与现有 `Persisted` 结构并列
- 约束：Pro 专属（免费版不显示入口）

### 4.4 名字 PK 🆕（优先级 P2）

- 多个候选并排：七维雷达叠加、读感、谐音体检、喜好度打分
- 免费限 2 个，Pro 限 4~6 个

## 5. 付费墙挂点（精确到现有代码）

**总原则**：付费墙出现在「价值感最高的一刻」，**不做冷启动弹窗**。

| 挂点 | 现有位置 | 行为 |
| --- | --- | --- |
| 结果页「查看全部」 | `ResultView.swift:174` | 免费点开只列 20 条，底部 Pro 提示条 |
| 结果页「换一批」 | `ResultView.swift:177` | 免费超出次数后弹 Pro |
| 详情页「备选名」 | `DetailView.swift:80` | 免费列表底部渐隐 + 「解锁全部」 |
| 详情页「收藏」 | `DetailView.swift:81` | 超过 5 个弹 Pro |
| 详情页「生成分享卡片」 | `DetailView.swift:27` | 免费出带水印图，导出前提示升级 |
| 英文名详情卡片 | `EnDetailView.swift:42` | 同上 |
| 自选姓名预览卡片 | `EnView.swift:161` | 同上 |
| 工作台选姓 / 选字 | `StudioSurnameView.swift` / `StudioCharView.swift` | 免费只见常见姓与精选字，筛选条顶部提示 |
| 西名中起生成 | `TranslitView.swift:55` | 免费 3 次/天，超出弹 Pro |
| 详情页「小名昵称」🆕 | `DetailView.swift` pill 行 | 免费只见叠字 2 个 |
| 详情页「试听」🆕 | `DetailView.swift` 名字下方 | 免费只读拼音，喇叭按钮锁 |
| 「我的」Pro 卡片 | `MineView.swift` 顶部 🆕 | 常驻：状态 + 升级/已解锁 |
| 设置「恢复购买」 | `SettingsView.swift` 🆕 | **App Store 强制要求** |

**付费墙组件**：新建 `ProGate.swift`，统一提供
- `ProBadge`（小锁标 / PRO 胶囊）
- `ProLockRow`（列表末尾的渐隐解锁条）
- `ProSheet`（权益对比 + 价格 + 购买 + 恢复购买 + 条款链接）
- 环境读取：`@Environment(ProStore.self)`

**免费额度实现**：在 `NamingAppModel` 加
- `var isPro: Bool`（从 `ProStore` 同步）
- `var freeQuota: FreeQuota`（按天计数的换一批 / 西名中起次数，存 `UserDefaults`，key 带日期）
- 所有额度判定集中一处 `func allowed(_ feature: ProFeature) -> Bool`

## 7. 技术架构（iOS）

```
Core/Store/
├── ProStore.swift        # @Observable：商品加载 / 购买 / 恢复 / 交易监听 / entitlement 缓存
├── ProFeature.swift      # enum：case allRecs / batchSwap / nickname / speech / family ...
└── FreeQuota.swift       # 免费额度计数（按天，UserDefaults）
Features/Pro/
├── ProSheet.swift        # 权益对比 + 定价 + 购买
├── ProLockRow.swift      # 列表锁定条
└── ProBadge.swift        # PRO 标识
```

`ProStore` 关键行为：

```swift
@Observable
final class ProStore {
    static let productID = "com.deernames.pro.lifetime"

    var isPro = false
    var product: Product?
    var purchasing = false

    func start() async            // 加载商品 + 校验当前 entitlement + 启动监听
    func purchase() async         // 发起购买、校验、写缓存
    func restore() async          // AppStore.sync() + 重新校验
    private func listen()         // Transaction.updates 长监听
    private func verify() async   // Transaction.currentEntitlements → 缓存到 UserDefaults
}
```

要点：
- **entitlement 先读本地缓存，再异步校验**，避免冷启动闪付费墙（离线也能用）
- `Transaction.updates` 必须长监听，处理退款 / 家庭共享 / 跨设备
- 不接自建服务器（纯离线，无需收据校验服务）；Apple 端 `currentEntitlements` 足够
- 免费额度计数**只在本地**，接受越狱绕过（成本远低于收益）

## 8. 埋点与验收

**埋点**（本地 `UserDefaults` 计数即可，后续再接分析）：
- paywall 展示次数 / 来源挂点
- 购买开始 / 成功 / 取消
- 免费额度触顶次数（换一批 / 西名中起 / 收藏）
- 昵称功能使用率（判断 P0 是否成立）

**验收标准**
- 免费用户能完成完整闭环：测性格 → 选姓 → 看 3 条推荐 → 进详情 → 生成带水印卡片
- Pro 购买 → 立即解锁，无需重启
- 「恢复购买」在换机 / 重装后可恢复
- 离线冷启动不误判为非 Pro

## 11. 风险与待定

| 风险 | 应对 |
| --- | --- |
| 免费线砍太狠 → 差评 | 详情页永完整；免费每批 3 条足够看到「好名字长什么样」 |

| H5 与 iOS 功能分叉 | 引擎层（`engine.js` ↔ `NameEngine.swift`）保持同源，Pro 只做 gate 不做算法分叉 |
